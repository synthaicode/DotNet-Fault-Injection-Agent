# 同期SQL呼び出し一箇所の介入検証

.NET Framework 4.8向けのx64テストプログラムです。ローカルの SQL Server LocalDB の MSSQLLocalDB を使い、同一接続内に一時テーブルと一時ストアドプロシージャを作成します。接続終了で一時オブジェクトは破棄されます。

リポジトリのルートで `dotnet build poc/SqlTarget -c Release` を実行し、生成された SqlTarget.exe を使います。[拡張のビルドと起動条件](../ProfilerRewrite/README.md)に従い、プロファイラー無効、拡張あり、プロファイラー無効の順に、同じEXEを起動します。

| 起動 | 選択した箇所 | 別の箇所 | DBの記録行数 |
|---|---|---|---:|
| 無効 | 成功 | 成功 | 2 |
| 拡張あり | TimeoutException | 成功 | 1 |
| 無効 | 成功 | 成功 | 2 |

全起動の終了コードは0で、試験前後のEXEのSHA-256は一致しました。エンジンのログにも選択したメソッドの書換え成功が記録されました。

選択箇所のILでは、ソース上の SqlCommand からの呼び出しが DbCommand.ExecuteNonQuery の仮想呼び出しとして記録されます。拡張はその呼び出し命令を、テストEXEにあらかじめ組み込んだ専用ヘルパーへの呼び出しに置き換えます。ヘルパーはSQL APIに進まず例外を投げます。DB側はプロシージャが行ったINSERTの件数を確認しています。SQL通信のトレースはこの検証では採取していません。

対象は固定のテストメソッドです。実行時のプロシージャ名などの条件照合、既存アプリへのヘルパー提供、Roslynと配布物の対応確認、SqlExceptionによるSQLタイムアウト再現は未実装です。
