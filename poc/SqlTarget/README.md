# 同期SQL呼び出し一箇所の介入検証

.NET Framework 4.8向けのx64テストプログラムです。ローカルの SQL Server LocalDB の MSSQLLocalDB を使い、同一接続内に一時テーブルと二つの一時ストアドプロシージャを作成します。接続終了で一時オブジェクトは破棄されます。

リポジトリのルートで `dotnet build poc/SqlTarget -c Release` を実行し、生成された SqlTarget.exe を使います。[拡張のビルドと起動条件](../ProfilerRewrite/README.md)に従い、プロファイラー無効、拡張あり、プロファイラー無効の順に、同じEXEを起動します。

| 起動 | 選択した箇所で対象プロシージャ | 別の箇所で対象プロシージャ | 選択した箇所で別プロシージャ | 一致する二回目の呼び出し | DBの記録行数 |
|---|---|---|---|---|---:|
| 無効 | 成功 | 成功 | 成功 | 成功 | 4 |
| 拡張あり | TimeoutException | 成功 | 成功 | 成功 | 3 |
| 無効 | 成功 | 成功 | 成功 | 成功 | 4 |

全起動の終了コードは0で、試験前後のEXEのSHA-256は一致しました。エンジンのログにも選択したメソッドの書換え成功が記録されました。

選択箇所のILでは、ソース上の SqlCommand からの呼び出しが DbCommand.ExecuteNonQuery の仮想呼び出しとして記録されます。拡張はその呼び出し命令を、テストEXEにあらかじめ組み込んだ専用ヘルパーへの呼び出しに置き換えます。ヘルパーは接続先、DB、コマンド種別、プロシージャ名が固定条件に一致する場合に、SQL APIに進まず例外を投げます。一致した最初の一回だけ発火枠を取得し、以降の一致と不一致は元のAPIを呼びます。別箇所と不一致の呼び出しを先に実行し、発火枠を消費しないことも確認しました。条件不一致の試験ではプロシージャ名だけを変えています。DB側はプロシージャが行ったINSERTの件数を確認しています。SQL通信のトレースはこの検証では採取していません。

SqlTarget.exe に --concurrent を渡すと、別々の接続を使う二つのタスクがバリアで揃ってから同じ対象箇所を呼びます。拡張ありでは一方だけが TimeoutException になり、もう一方は正常に終了しました。拡張なしでは両方が正常に終了しました。発火枠はプロセス起動ごとに初期化されます。

対象は固定のテストメソッドです。条件と発火回数の外部設定、既存アプリへのヘルパー提供、Roslynと配布物の対応確認、SqlExceptionによるSQLタイムアウト再現は未実装です。
