# AIによる注入計画の作成

利用者は業務処理と試験したい障害を指定します。AIは意図を整理し、Roslynが抽出した候補と結び付けます。実行対象の識別情報は、SourceMapがソースと配布物を照合して生成します。

## 利用者と決めること

- **呼び出し箇所**。SourceMapの候補一覧から、呼び出し元、ソース位置、呼び出すAPI、選定理由を示します。同じプロシージャを別の箇所から呼ぶ場合は候補を区別します。実行時に決まる値は、その時点での確定値として扱いません。
- **照合条件**。接続先、DB、プロシージャ名を確認します。条件はすべて一致した場合に適用されます。接続先とDBはアプリが開いた接続との照合に使います。
- **障害と回数**。例外処理に分岐がある場合は、ソース上の捕捉型と判定条件を示します。現PoCは同期ExecuteNonQueryの呼び出し前にTimeoutExceptionを投げる試験に対応します。SqlExceptionの特定番号、非同期API、SQL処理後の応答喪失が必要なら、対応外の理由を示して指定を止めます。利用者が希望した障害を別の例外に置き換える場合は、試験の目的を改めて確認します。

たとえば「注文確定処理から対象ストアドを呼ぶときだけ一回失敗させたい」という指定なら、対象の呼び出し元ともう一方の候補を示し、対象行、接続先、DB、プロシージャ名、送信前のTimeoutException、一回という上限を確認します。対応する候補が一意に決まらない場合は、選択に必要な情報を確認します。

## 1計画1ファイルの作り方

1. 実行予定のEXE、対応するPortable PDB、対応するソースを用意し、SourceMapの list で候補を取得します。
2. 利用者が確認した行を指定し、[SourceMapの手順](README.md)で新規JSONを生成します。照合に失敗したら、配布物とソースの組み合わせを確認します。
3. JSONをパースし、利用者が確定した4項目を設定して保存します。既存の計画と区別できる名前を使います。残りの項目はSourceMapの出力をそのまま使います。

| JSONキー | 入力と意味 |
|---|---|
| server | SqlClientが返す接続先。大文字・小文字を区別せず比較 |
| database | SqlClientが返すDB。大文字・小文字を区別して比較 |
| procedure | コマンドのプロシージャ名。大文字・小文字を区別して比較 |
| maxFirings | プロセス内の発火上限。0から2147483647までの整数。0は発火なし |

文字列3項目は空文字、CR、LF、NULを受け付けず、各値はUTF-8で最大1024バイトです。コマンド種別はStoredProcedureに限定されます。無効中や条件不一致では発火枠を消費しません。再有効化しても残りの発火枠を引き継ぎます。

SourceMapが出力する項目は version、sha256、mvid、methodToken、ilOffset、call、fault です。AIが識別値を推測したり、照合エラーに合わせて書き換えたりすると、利用者が確認した箇所との対応を失います。実行するEXEが変わったらSourceMapで再照合し、新しい計画を生成します。余分なキーや重複キーを加えず、計画全体を64 KiB以内に収めます。

## 結果の伝え方

計画を作成した段階では、利用者が確定した対象・条件、生成したファイル、試験が再現する範囲を返します。実行を依頼された場合は、[検証用ランチャー](../SqlTarget/README.md)の結果から、計画の受理・拒否、IL書換え、発火回数をそれぞれ報告します。既存Windowsサービスへの適用は未検証です。

## 一度に複数の箇所を指定する

箇所ごとに選定理由、条件、障害、発火上限を確認します。複数箇所を選んだら、[複数行の指定](README.md#複数箇所の計画)で一つのJSONを生成し、rules 配列の各要素の条件4項目を設定します。発火枠はルールごとに独立します。実行結果はランチャーの FiringsByMethod を計画の methodToken と突き合わせ、利用者にはソース上の箇所名で伝えます。


保存後はSourceMapの verify で計画の内容とソース・PDB・EXEの対応を確認します。
